GRAVITY CHAIN

Audiovisual signal is processed into a file. The file is probed. The tesseract is the address that file receives. Sixteen vertices. The 4D audio vector is the metadata stored on the chosen vertex.

1 SIGNAL

picture

yt-dlp into ~/Downloads. H.264 at the source pixel size. GIF, theta rotate, and VP56 are sibling products of the same download.

sound

soxr 48 kHz on a re-encode. Optional peak or loudness gain. Gravity splits the programme into discrete WAVs plus mix.wav.

file

The mint target is the finished media file, not each channel WAV. A direct download calls interlatus mint when the file is closed.

▼

2 PROBE

ffprobe

Duration, size, bitrate, width, height, video codec, audio codec. First video stream and first audio stream.

sha256

Hash of the file bytes. The same digest picks the pattern code and the vertex. A repeated hash returns the existing cell.

audio_vector

Four floats, capped at 2: duration/600, size MB/500, Mbit/s/10, width/height. This is probe metadata, not a waveform.

▼

3 TESSERACT · CORE ADDRESS

VERTEX [x, y, z, t] · EACH AXIS IS 0 OR 1

Four low bits of the content hash, one per axis. Y H W H names the axes x y z t. A Gray-code walk flips one bit per step and closes after 16.

4 CATALOG

registry

SQLite blockcode_registry.db stores pattern, vertex, owner, sha256, and the metadata JSON that holds audio_vector.

sidecar

<file>.interlaterus.json sits beside the media. nls_media_catalog.json lists pattern, vertex, and audio_vector.

POS

pos_reconcile pairs the file (AVD) with its vertex (POS). Proof of spatio hashes that index. Capacity is 16 cells.
